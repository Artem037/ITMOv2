# Unit-проверки

| ID / правило | Что проверяем изолированно | Вход | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| `UT-SEC-1` / `SEC-1` | `SecretRedactor` распознаёт типовые секреты. | Diff с token, password и блоком private key. | Секреты заменены на `[REDACTED]`; остальной diff сохранён. | Сравнение результата с fixture; исходные секреты отсутствуют. |
| `UT-SEC-2` / `SEC-1` | Обычный код не повреждается. | Diff без секретов и строки, похожие на короткие идентификаторы. | Результат совпадает со входом; ложного редактирования нет. | Parametrized fixture benign values. |
| `UT-API-1` / `API-1` | Граничная проверка длины. | Строки длиной 19 999, 20 000, 20 001. | Первые две допустимы; 20 001 порождает доменную ошибку `DiffTooLarge`. | Три независимых assertion. |
| `UT-OUT-1` / `OUT-1` | Валидатор структуры ответа. | Корректный ответ; 4 риска; отсутствие `evidence`; поле `comment`. | Корректный принят; остальные отклонены с понятной причиной. | Таблица параметров и schema validation. |
| `UT-QA-1` / `QA-1` | Проверка доказательства риска. | Risk со строкой, присутствующей в diff; risk с неизвестным файлом/строкой. | Первый сохранён, второй отклонён. | Assertion итогового массива `risks`. |
| `UT-REL-1` / `REL-1` | Настройка adapter timeout и преобразование исключений. | Fake transport: success, timeout, generic error. | Success возвращён; timeout → controlled timeout error; ошибка → controlled dependency error. | Fake clock/transport без реальной сети. |
| `UT-OBS-1` / `OBS-1` | Формирование события лога. | request_id, duration, status и объект с diff/LLM response. | Событие содержит только разрешённые три поля. | Сравнение ключей и поиск маркерной строки секрета. |

Проверки описывают целевой набор; имена файлов тестов будут зафиксированы при реализации следующей практики. На этом этапе выполнение кода не заявляется.
