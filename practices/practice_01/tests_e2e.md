# E2E-проверки

| ID / сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| `E2E-1` Позитивный | Сервис поднят; test LLM возвращает валидные доказанные риски. | Ревьюер отправляет допустимый diff. | HTTP 200; `summary`, ≤3 `risks`, `checks`; у каждого риска заполнены `file`, `line`, `evidence`, `risk`. | Сохранённые request/response и проверка JSON schema. |
| `E2E-2` Секрет в diff | Test LLM-spy доступен; включён capture безопасных логов. | Отправить diff с уникальным тестовым token. | HTTP-ответ контролируем; spy получил `[REDACTED]`; token отсутствует в spy payload, ответе и логах. | Captured sanitized prompt и log scan. |
| `E2E-3` Негативный timeout | Test LLM задерживает ответ >10 сек. | Отправить допустимый diff. | Не позже 10 сек LLM-вызов прерван; клиент получает выбранный ADR контролируемый HTTP 504; сервис остаётся доступен. | Duration, status/body, последующий `/health` = 200. |
| `E2E-4` Граница размера | Сервис поднят; LLM-spy обнулил call counter. | Последовательно отправить 20 000 и 20 001 символ. | 20 000 проходит в pipeline; 20 001 → HTTP 413; второй запрос не увеличивает call counter. | Два ответа и call counter. |
| `E2E-5` Недоказанный вывод | Test LLM возвращает риск по файлу/строке, которых нет в diff. | Отправить допустимый diff. | Риск не выдаётся как подтверждённый; ответ остаётся по schema либо возвращается контролируемая ошибка валидации. | Response и validation log metadata. |
| `E2E-6` Границы полномочий | Test LLM включает совет выполнить merge. | Отправить допустимый diff. | Сервис не вызывает GitHub и не меняет файлы; пользователь получает только advisory-результат в разрешённой схеме. | Отсутствие исходящих GitHub calls и изменений состояния. |

## Трассировка

- `E2E-1` → `OUT-1`, `QA-1`.
- `E2E-2` → `SEC-1`, `OBS-1`.
- `E2E-3` → `REL-1`.
- `E2E-4` → `API-1`.
- `E2E-6` → `SCOPE-1`.

## Как использовали AI

- Для чего: собрать сквозную приёмку от HTTP-входа до наблюдаемого ответа и внешних эффектов.
- Тип промпта: homework master prompt.
- Строка в [`prompts.md`](prompts.md): `P1-03`.
- Что проверили и исправили сами: добавили трассировку ко всем правилам и не заявляли выполнение ещё не реализованных тестов.
