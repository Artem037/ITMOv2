# Планировщик загородных поездок — домашняя работа 4

Собственный skill `transit-trip-planner` помогает выбрать до пяти времён
выхода с учётом редких рейсов, переходов и запаса на посадку. Расчёт выполняет
собственный MCP tool `plan_departures`.

## Запуск

Из корня репозитория на ветке `homework_04` (Python 3.12+, uv):

```sh
make -C practices/practice_04/homework install
sh scripts/check.sh
opencode
```

Node.js нужен для проверки hook. Runner использует `node` из PATH или
Node.js из стандартного bundled runtime приложения. Установка зависимостей
однократная; проверки выполняются offline. Официальный MCP SDK 2.3.0,
Pydantic и Ruff 0.16.10 зафиксированы в `uv.lock`.

В OpenCode попросить: «Используй transit-trip-planner и предложи варианты
выхода по ...». В `opencode.json` уже подключены собственный `trip_planner`
и готовый `fetch`. Запускать OpenCode из корня этого checkout.

## Проверка без агента

```sh
uv run --directory practices/practice_04/homework --locked --offline \
  python -m trip_planner.cli validate \
  --input tests/fixtures/rare_connections.json
uv run --directory practices/practice_04/homework --locked --offline \
  python -m trip_planner.cli plan \
  --input tests/fixtures/rare_connections.json
make -C practices/practice_04/homework mcp-smoke
make step4
```

С `uv --directory practices/practice_04/homework` пути `--input` и
`--output` считаются от каталога `homework`; абсолютные пути также допустимы. CLI
возвращает exit 2 и понятную ошибку для неправильного входа. `plan` нужен
для повторной проверки человеком; доказательство MCP — настоящий вызов
сервера, а не эта команда.

## Как это работает

- Skill собирает ограничения и читает официальные расписания через fetch
  или браузер, проверяет дату, направление и остановки, нормализует JSON.
- `models.py` проверяет структуру, хронологию, источники и переходы.
- `planner.py` вычисляет достижимые сочетания, обратным счётом определяет
  выход, сортирует по полному времени, ожиданию и числу пересадок. Для
  каждого времени выхода остаётся лучший маршрут.
- `server.py` предоставляет эту функцию через MCP stdio. Неправильный вход
  возвращает ошибку; сервер остаётся доступным.
- Hook возвращает результат `scripts/check.sh` после значимых правок.

Подробный формат находится в [ресурсе skill](../../../.opencode/skills/transit-trip-planner/references/input-and-sources.md).
При переносе нужны каталог skill, весь `homework` с lock-файлом и запись
MCP из `opencode.json`. Алгоритм не копируется внутрь skill.

## Примеры и ограничения

`tests/fixtures/rare_connections.json` — полностью вымышленные расписания.
`examples/tolmachevo-2026-10-14.json` — реальные поездные часы на 14.10.2026
и оценочные городская/пешая части; точный домашний адрес в файл не включён.
Это сохранённый пример проверки, а не автоматически обновляемое расписание.
Перед поездкой требуется новый контроль источников и изменений.

В первой версии нет Яндекс API-адаптера. Источники собирает агент и
проверяет через CLI; MCP автоматизирует расчёт. Ключи и платные сервисы
этому режиму не нужны. Выбор источников: [SOURCE_CHECK.md](SOURCE_CHECK.md).

Оптимум ищется только среди переданных цепочек, максимум три участка
с точными расписаниями. `no_routes` не означает отсутствие транспорта
вообще; `needs_data` означает нехватку подтверждённых данных.
Городские и пешие длительности оценочные; `null` означает неизвестное
время, а не ноль. `waiting_minutes` и `transfer_count` относятся к участкам
с расписаниями; ожидание метро входит в оценку городского участка.

Для контрольного маршрута автобусные промежуточные часы не подтверждены.
Проверяемый вариант через Толмачёво включает около 9,2 км пешком; подходит
только при согласии путешественника на такую прогулку. Геометрия карты
не гарантирует фактическую проходимость тропы и не включает отдых.
