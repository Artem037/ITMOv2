# Нагрузочные проверки (кандидат, RCTF)

Исходная версия: practices/practice_02/few_shot/tests_load_candidate.md. Правила — practices/practice_01/CASE.md (нельзя изменять).

Цель: сохранить полезные сценарии, сделать их доказательными и воспроизводимыми. Чётко разделяем:
- Hard Requirements — подтверждённые правила из CASE.md с ссылками;
- Test Parameters — настройки конкретного прогона/baseline;
- Hypotheses — наблюдаемые метрики и инженерные предположения; не SLO и не критерии прохождения.

Связанные требования из CASE.md:
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- SEC-1: до внешнего LLM из diff удаляются токены, пароли и приватные ключи.
- OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответа модели не логируется.

Легенда меток:
- [ТРЕБОВАНИЕ] — подтверждённое правило из CASE.md;
- [ПАРАМЕТР] — настройка конкретного тестового прогона/baseline;
- [ГИПОТЕЗА] — наблюдение/предположение для baseline, не SLO.

## Инструментирование и baseline

- LLM-stub и spy:
  - Режимы stub: fixed-latency [ПАРАМЕТР] и no-response [ПАРАМЕТР].
  - LLM-spy собирает: timestamp, request_id, факт вызова, длительность, и «sanitized» prompt (без содержимого diff; допускается захват только индикаторов редактирования).
- Генератор diff:
  - Детерминированный контент с seed [ПАРАМЕТР].
  - Длины: 20 000 и 20 001 символ [ПАРАМЕТР].
  - Встраиваемые маркеры секретов для LT-4: токен вида sk_test_<UUID4>, пароль p@ss-<unique>, приватный ключ BEGIN PRIVATE KEY...END [ПАРАМЕТР].
- Метрики и артефакты:
  - Нагрузочный отчёт (latency p50/p95/p99, throughput, статус-коды, error rate) [Evidence].
  - Spy-трассы LLM (вызовы/таймауты/редакция секретов) [Evidence].
  - Снимки RSS/CPU/GC, если доступны [Evidence].
  - Скан логов на отсутствие контента diff/LLM и маркеров секретов [Evidence].

### LT-0. Baseline discovery (новый)

- Test Parameters:
  - Профиль: ступенчатая нагрузка 5 -> 10 -> 50 RPS [ПАРАМЕТР]; длительность ступени 2 минуты [ПАРАМЕТР].
  - LLM adapter: stub fixed-latency 100 мс [ПАРАМЕТР].
  - Набор диффов: валидные ≤ 20 000 символов [ПАРАМЕТР].
- Hard Requirements: нет (этап разведки baseline, без gating).
- Hypotheses: фиксируем p95/p99, error rate, ресурсы как отправную точку; без порогов.
- Что измеряем: латентность, throughput, статусы, ресурсы.
- Evidence: отчёт нагрузочного инструмента и метрики.

## Сценарии

### LT-1. Валидация без внешнего LLM

- Test Parameters:
  - 50 RPS [ПАРАМЕТР], 10 минут [ПАРАМЕТР]
  - Смесь диффов: 20 000 [ПАРАМЕТР] и 20 001 [ПАРАМЕТР] символов
  - LLM adapter: stub [ПАРАМЕТР]
- Hard Requirements:
  - Для oversized 100% HTTP 413 [ТРЕБОВАНИЕ API-1]
- Hypotheses:
  - Наблюдать p95 [ГИПОТЕЗА]
  - Наблюдать отсутствие неконтролируемых 5xx [ГИПОТЕЗА]
  - Наблюдать отсутствие LLM calls для oversized по spy [ГИПОТЕЗА]
- Что измеряем: RPS, p95/p99, error rate, LLM call count.
- Evidence: отчёт k6/Locust и метрики/spy; отчёт проверки статусов 413.

### LT-2. Номинальный LLM stub

- Test Parameters:
  - 10 RPS [ПАРАМЕТР], 10 минут [ПАРАМЕТР]
  - 20 одновременных клиентов [ПАРАМЕТР]
  - Stub latency 100 мс [ПАРАМЕТР]
- Hard Requirements:
  - Логи не содержат diff/LLM-контента, только request_id/длительность/статус [ТРЕБОВАНИЕ OBS-1]
- Hypotheses:
  - Наблюдать p95 [ГИПОТЕЗА]
  - Наблюдать долю успешных ответов [ГИПОТЕЗА]
  - Наблюдать тренд памяти (не превращать в критерий) [ГИПОТЕЗА]
- Что измеряем: latency, throughput, статус-коды, RSS.
- Evidence: нагрузочный отчёт, график ресурсов, лог-скан на отсутствие контента.

### LT-3. Timeout saturation

- Test Parameters:
  - 5 RPS [ПАРАМЕТР], 2 минуты [ПАРАМЕТР]
  - Stub никогда не отвечает (no-response) [ПАРАМЕТР]
- Hard Requirements:
  - 100% запросов получают контролируемый ответ (без падений/traceback; единообразный статус) [ТРЕБОВАНИЕ REL-1]
  - Таймаут внешнего LLM-вызова 10 секунд (per-call) [ТРЕБОВАНИЕ REL-1]
- Hypotheses:
  - Наблюдать распределение E2E времени ответа [ГИПОТЕЗА]
  - Наблюдать восстановление `/health` после снятия нагрузки [ГИПОТЕЗА]
- Что измеряем: общая длительность, доля 504/ошибок, число занятых workers, время восстановления.
- Evidence: отчёт, application metrics, spy-трассы с таймаутами ~10с.

### LT-4. Безопасность логов под нагрузкой

- Test Parameters:
  - Повторить LT-2 [ПАРАМЕТР]
  - Уникальные маркерные секреты в diff [ПАРАМЕТР]
- Hard Requirements:
  - 0 маркеров секретов в логах (содержимое diff/LLM не логируется) [ТРЕБОВАНИЕ OBS-1]
  - Секреты удаляются до внешнего LLM [ТРЕБОВАНИЕ SEC-1]
- Hypotheses:
  - Наблюдать, что на каждый запрос не более одного итогового metadata-event [ГИПОТЕЗА]
- Что измеряем: объём логов, поиск маркеров, поведение санитайзера и LLM-spy.
- Evidence: sanitized log scan и отчёт LLM-spy (маркеры заменены на [REDACTED]).
