# Нагрузочные проверки — кандидат после аудита (Practice 2)

В `CASE.md` нет throughput/SLO, а реальная LLM-инфраструктура не дана. Числа ниже — стартовая инженерная гипотеза для baseline, а не подтверждённое требование. После первого staging-прогона владелец сервиса должен утвердить или изменить пределы.

Легенда пометок:
- [ТРЕБОВАНИЕ] — подтверждённое правило из `CASE.md` (ссылка на ID);
- [ПАРАМЕТР] — настройка конкретного тестового прогона/baseline;
- [ГИПОТЕЗА] — предварительный порог для baseline, не является утверждённым SLO.

Подтверждённые требования из CASE.md (релевантные нагрузочным проверкам):
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413. [ТРЕБОВАНИЕ API-1]
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. [ТРЕБОВАНИЕ REL-1]
- SEC-1: до внешнего LLM из diff удаляются токены, пароли и приватные ключи. [ТРЕБОВАНИЕ SEC-1]
- OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответа модели не логируется. [ТРЕБОВАНИЕ OBS-1]

Реальный внешний LLM не используется в регулярном load-тесте, чтобы не создавать неконтролируемую стоимость и не отправлять тестовые секреты. Отдельный staging smoke-тест выполняется только после согласования лимитов и бюджета.

## Что изменилось в сравнении с исходным планом

- Убрали непроверяемый критерий «память не растёт монотонно» из pass/fail для `LT-2`; оставили как наблюдаемую метрику без порога (TBD), поскольку в `CASE.md`/`context.md`/`problem.md` нет числового бюджета памяти.
- Заменили «504 rate» в метриках `LT-3` на «доля контролируемых таймаут-ответов (HTTP-статус TBD по ADR)», чтобы не фиксировать код, не заданный в `CASE.md` и пока лишь предложенный в `adr.md`.
- Добавили проверку `SEC-1` под нагрузкой в `LT-2`: генерация маркерных секретов и подтверждение 0 утечек до LLM по отчёту LLM-spy.

## Как использовали AI

- Для чего: провести ограниченный evidence-based аудит и исправить три наиболее существенные проблемы по приоритетам задания.
- Тип промпта: ReAct audit на основе артефактов практики 1.
- Что проверили и исправили сами: отделили гипотезы от требований, исключили неподтверждённый HTTP-код из метрик, добавили воспроизводимый тест на `SEC-1` под нагрузкой.
