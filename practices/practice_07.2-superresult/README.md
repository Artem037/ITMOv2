# Сверхрезультат 7.2 · исправление бага через n8n

[Условие задания](../practice_07.2/README.md#задача-на-сверхрезультат-10-баллов) · [План](PLAN.md) · [Экспорт n8n](workflow.json) · [Пруф](proof.md)

n8n ищет открытый GitHub Issue с меткой `autofix`, воспроизводит описанный сбой через локальный исполнитель и получает от Codex выражение для исправления. После регрессионных проверок исполнитель коммитит изменение, пушит отдельную ветку и открывает PR. Для ревью n8n вызывает модель второй раз и публикует её вердикт в PR. Условие в n8n ведёт к merge только при положительном вердикте. Исполнитель перед merge сверяет проверенный коммит и текущую основную ветку.

Тестовый проект взят из упражнения по ревью. В нём `applyDiscount(total, percent)` увеличивал сумму при скидке. Исполнитель рассчитан на этот модуль и принимает числовые bug reports от владельца отдельного приватного репозитория `<owner>/itmo-7-2-bugfix-demo` с основной веткой `master`.

## Запуск

Нужны Node.js 24, n8n 2.x, Git, `gh` и Codex CLI. `gh` и Codex должны быть авторизованы. Для второго экземпляра n8n укажите отдельный каталог данных через `N8N_USER_FOLDER`. [Команды n8n CLI](https://docs.n8n.io/deploy/host-n8n/configure-n8n/use-the-command-line/)

Из этой папки проверьте правила и запустите исполнитель.

```bash
node --test
ITMO_AUTOFIX_REPO=Artem037/itmo-7-2-bugfix-demo node worker.mjs
```

Исполнитель слушает `127.0.0.1:8763`. Импортируйте `workflow.json` в локальный n8n. Для разового прогона используйте ручной триггер или CLI.

```bash
n8n import:workflow --input=workflow.json
n8n execute --id=Itmo72AutofixV1
```

Для опроса очереди опубликуйте workflow в локальном n8n. Schedule Trigger вызывает ту же цепочку каждую минуту. В тестовом репозитории Issue с меткой `autofix` содержит четыре строки.

```text
component: discount
total: 100
percent: 10
expected: 90
```

Уже исправленный пример, неподходящий отчёт, проваленная регрессия или серьёзное замечание прекращают проход до merge. Существующий PR для Issue исключает повторную обработку при перезапуске исполнителя.

На стенде с Colima n8n запущен в выделенном контейнере, а исполнитель работает на macOS. Для такого запуска в копии импорта замените `127.0.0.1` на `host.lima.internal` в адресах HTTP-нод.
