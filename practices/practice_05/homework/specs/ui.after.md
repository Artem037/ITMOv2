настоящий расчёт без ручного JSON и понять причину отсутствия варианта.

### Один экран и сущности

Порядок: маршрут и учебная пометка → даты/МСК → форма с четырьмя параметрами
→ кнопка и состояние → актуальный итог/причина → предупреждения, источники,
область поиска. Источник `synthetic` остаётся учебным при `verified=true`.
Ожидание/пересадки подписываются как относящиеся к расписанным этапам.

| Сущность | Данные | Ответственность |
| --- | --- | --- |
| Инициализация | route/timezone/data_kind/schedule_dates/sources/defaults/limits из C-02 | Адаптер предоставляет, UI показывает |
| Поля | Две даты-времени, запас и лимит; до проверки хранятся как текст | UI редактирует и проверяет, сервер проверяет повторно |
| Отправка | Копия параметров, локальная редакция и номер запроса | UI связывает ответ с текущим вводом, не посылает эти ID серверу |
| Ответ | Полный PlanResult без обёртки | Ядро считает, UI показывает без потери полей |
| Ошибка | error.code/message и необязательный field | Адаптер формирует; UI показывает поле или общую причину |

### Состояния и переходы

Загрузка/ошибка метаданных предшествуют готовой форме. После загрузки:

| Состояние | Содержание и переход |
| --- | --- |
| initial | Defaults, расчёта нет; изменение → editing, отправка → проверка |
| editing | Старого итога нет; явная отправка → invalid либо pending |
| invalid | Ввод и ошибки сохранены; исправление → editing, повтор разрешён |
| pending | Ожидание; изменение → editing и неактуальность старого запроса; актуальный ответ → соответствующий исход |
| success | Варианты и вся сопровождающая информация; complete=false видим отдельно |
| no_routes | Честное отсутствие вариантов и вся сопровождающая информация |
| needs_data | Нехватка подтверждения и вся сопровождающая информация |
| transport_error | Проблема связи/ответа, поля сохранены, ручной повтор разрешён |

Из результата изменение ведёт в editing. Поздний ответ старой редакции
вообще не вызывает переход. Только локальный номер/редакция управляет
актуальностью; отмена ожидания не обещает остановить Python-расчёт.

## 3. Измеримые исходы

- **UI-SC-001:** исходный экран после отправки показывает ровно один вариант
  09:35–11:50/135 минут, четыре участка, источник и учебную пометку.
- **UI-SC-002:** запас 20 показывает 09:25–11:50/145, старого итога нет.
- **UI-SC-003:** два отрицательных окна дают два различных объяснения C-04.
- **UI-SC-004:** пустота, дробь, диапазон и обратное окно объяснены; исправление
  и успех доступны без перезапуска, равные границы и крайние целые допускаются.
- **UI-SC-005:** минимум в двух зонах компьютера московские поля/часы совпадают.
- **UI-SC-006:** при обоих порядках A/B и поздней ошибке A экран ни разу
  не принимает A вместо актуального B; двойная отправка не дублирует редакцию.
- **UI-SC-007:** для всех трёх исходов доступны все warnings/sources/область;
  partial ok сохраняет вариант и неполноту, дробные длительности не потеряны.
- **UI-SC-008:** успех, исправление и повтор после сбоя доступны с клавиатуры.

Прежние сценарии с учебными часами проверяются фиксированным запуском --fixture. Связь AC1–AC5 и UI/логики/контракта/доказательств находится в C-07.
Для проверки актуальности допустимы управляемые задержки; основной сценарий
и ошибка/граница требуют настоящего браузера и ядра, а не только моков.

## 4. Допущения и границы

Один локальный пользователь и фиксированный учебный снимок, обычные
HTML/CSS/JavaScript, loopback Python-адаптер. Нет адресного поиска, карт,
живых расписаний, загрузки данных, хранения поездок, авторизации и облака.
Форма не обновляет подтверждения и не обещает актуальность прошлых данных.

UI-Q-001 решён C-02–03: отдельный GET и точное тело POST, московский offset.
UI-Q-002 решён C-05: error с необязательным field, собственные стабильные
полевые проверки адаптера, без разбора текста ядра. UI-Q-003 решён C-06:
редактирование разрешено, повтор редакции блокируется, таймаут 10 секунд,
локальная редакция отбрасывает старые ответы. Новых блокирующих вопросов
к интерфейсу нет; принятие человеком получено 27.10.2026.
