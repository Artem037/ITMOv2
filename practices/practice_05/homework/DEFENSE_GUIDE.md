## 6. Продемонстрировать приложение

Открой [форму](http://127.0.0.1:8765). Все времена — московские.
Сначала покажи маршрут, дату расписания, дату проверки и оценки пути.

| Шаг | Что ввести / сделать | Что должно получиться |
| --- | --- | --- |
| Исходный успех | 30.10.2026 06:00–10:00, запас 10, лимит 5 | 3 варианта; лучший **07:42 → 11:55, 253 минуты** |
| Пересчёт | Изменить запас на 20 | Старый итог исчезает; после расчёта **07:32 → 11:55, 263 минуты** |
| Нет вариантов | Вернуть запас 10; 30.10.2026 08:00–08:10 | `no_routes`: нет подходящих вариантов среди переданных подтверждённых цепочек |
| Не хватает данных | 31.10.2026 06:00–10:00 | `needs_data`: расписание на новый день не появилось |
| Ошибка и восстановление | Вернуть окно 30.10.2026 06:00–10:00; запас `1.5`, затем `10` | Понятная ошибка; после исправления — успешный расчёт без перезапуска |

При успехе прокрути результат: этапы пути, оценки, предупреждения,
ссылки на источники и область поиска должны быть видны.

**Пояснение к реальности данных:** расписание СЗППК сохранено на 30.10.2026,
проверено 29 октября. Подход к вокзалу **45 минут** и пешие **около 9,2 км / 115 минут**
— явно указанные оценки. Обновления расписаний во время запроса нет.
Подробности: [источники](/Users/pip/ITMOv2/practices/practice_05/homework/REAL_ROUTE_SOURCES.md).

Дополнительно, если спросят о полуночи: окно 30.10.2026 22:40–23:00,
запас 10. Рейс 6141: 30.10 23:45 → 31.10 01:48; к цели — 31.10 03:43.

Числа 09:35–11:50 / 135 минут в исходных критериях относятся к контрольному
вымышленному примеру. Он сохранён отдельной командой `serve-fixture`;
основной показ проводится на реальном снимке. Одновременно на одном порту

## Короткие ответы на вероятные вопросы

| Вопрос | Ответ |
| --- | --- |
| Почему две спеки, а не одна? | Разные зоны ответственности: UI описывает взаимодействие, логика — данные и операции; общий контракт связывает их. |
| Что нового в логике, если ядро уже было? | HTTP-адаптер, строгая проверка параметров формы, метаданные, безопасные ошибки и независимая копия снимка для каждого расчёта. |
| Что такое Spec Kit в этой работе? | SDD-фреймворк, организующий требования, план, задачи и проверку соответствия реализации. Это не сервер приложения. |
| Форма вызывает MCP? | Напрямую вызывает Python-ядро через HTTP-адаптер. MCP из ДЗ4 остаётся отдельным рабочим входом к тому же ядру. |
| Почему другие даты не считаются? | Загружен подтверждённый снимок расписания только на 30 октября. На неподтверждённую дату показываем нехватку данных. |
| Чем отличаются no_routes и needs_data? | В первом случае данных достаточно, но подходящих вариантов нет; во втором для вывода не хватает подтверждённых данных. |
| Это лучший маршрут вообще? | Лучший среди переданных цепочек, без поиска по всей транспортной сети. |
| Согласовали до кода — чем докажешь? | AGREEMENT и история: before — `ec5f8c9`, принятие — `91994f0`, план — `0c4c5d7`, реализация — `5165c87`. Реальные данные и обновление спецификаций — `3692527`, код расширения — `277f12a`. |

Короткие хеши выше относятся к исходной истории. В публикации от main
семь коммитов перенесены в том же порядке; соответствие исходных и новых
хешей — [publication-history.json](evidence/publication-history.json).
