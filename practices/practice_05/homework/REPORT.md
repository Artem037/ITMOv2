## Проверки и найденные проблемы

TDD-последовательность: 17 контрактных HTTP-проверок RED → адаптер GREEN;
12 браузерных сценариев RED отсутствующего экрана → форма GREEN;
новые пути hook RED → hook GREEN. RED/GREEN сохранены в evidence.
Тесты вычисления сравнивают полный ответ с сохранёнными примерами ядра,
а не вычисляют ожидание тем же helper, который проверяется.

Независимый review нашёл два реальных дефекта: неполная проверка вложенных
metadata включала неработающую форму; TRACE/CONNECT обходили согласованный
JSON-ответ 405. Визуальная проверка нашла третью проблему — AM/PM native-поля.
Для исправлений наблюдались отдельные RED, затем GREEN: типизированная
проверка metadata, общая маршрутизация неподдерживаемых методов и явный
24-часовой ввод. Итог: 17 HTTP- и 14 браузерных тестов.

Первая попытка RED методов упала на разборе HTML как JSON; assertion границы
уточнён, после чего RED явно показал 501 HTML вместо JSON. Аналогично ожидание
кнопки metadata заменено явным assertion. Ошибки прогонов сохранены, не скрыты.
Ruff выявил ненужные noqa, допустимую внешнюю границу Exception и длинные
строки; исправлены код/форматирование, runner и правила не ослаблялись.
Перед checkpoint документов whitespace-проверка сохранённого diff дала сбой,
но shell продолжил коммит; артефакт исправлен, факт записан, последующие команды
проверяли return code до продолжения.

Уникальные проверки после добавления ДЗ5: **89** тестов — 8 Notify Mini,
28 ДЗ4, 17 адаптера, 14 браузерных, 6 hook, 16 практики6.
`check.sh` выполняет 73 из них, `make test` — 83; повторные запуски общих
наборов не увеличивают число уникальных тестов. Старые CLI/stdio MCP входят
в 28 тестов ДЗ4. Проверки материалов практик1–2 и Ruff считаются отдельно.

Основные факты: 09:35–11:50/135 при запасе10; 09:25/145 при20;
no_routes в окне09:36–10:00; needs_data 15 октября; включённая09:35;
partial ok, дробные135.5, ошибки/повторы и отсутствие мутации. Браузер
проверен в зонах Moscow/New York и на ширине390px, включая клавиатуру.
Основная интеграция — реальный браузер → HTTP → ядро; контролируемые
транспортные сбои/задержки используются только для компонентных границ.

Официальные факты стандартной библиотеки проверены по Python Docs, URLs и
фактические вызовы записаны в [research](../../../specs/001-trip-planner-form/research.md).
Универсального fetch MCP в этой сессии нет; применён web fallback только

## Рефлексия по наблюдаемому процессу

Независимые before оказались полезны в конкретном месте: UI продумал
редактирование и поздние ответы, логика — строгие числа, снимок и неполноту.
Без явного выбора политики один экран мог бы блокироваться, а другой
компонент ожидать перекрывающиеся вызовы. Большинство требований совпали,
поэтому список искусственных конфликтов не понадобился.

Spec Kit помог связать требования с исполнимыми задачами и проверить пробелы,
но сами документы не обнаружили браузерный AM/PM и неполную валидацию metadata.
Это нашли скриншоты и независимый review; прогон только ядра тоже был бы
недостаточен. Полезной границей оказался контракт: UI формат изменился,
а московский ISO и арифметика остались прежними.

Для маленького фильтра на паре OpenSpec change/delta был компактнее. Для
этой истории дополнительные plan/data-model и C-07 оправданы двумя ролями
и транспортной границей. Ни один фреймворк не заменил RED/GREEN, человека
в точке принятия и реальный браузер. В следующей похожей работе полезно
раньше включать непригодные вложенные данные и локаль браузера в первые тесты.
