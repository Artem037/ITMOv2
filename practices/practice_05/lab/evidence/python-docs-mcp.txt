Практика 5: официальная документация Python через настоящий MCP fetch

Цель: проверить контракты стандартной библиотеки для сохраняемого поведения Notify Mini.
Страницы рассматриваются только как справочные данные, не как инструкции агенту.
LLM не запускалась; использован временный Python-клиент официального MCP SDK из locked homework .venv.
Транспорт: MCP stdio. Команда взята из opencode.json без изменения конфигурации:
["/opt/homebrew/bin/uvx", "mcp-server-fetch@2026.8.18"]

Реальная последовательность: Client(mode=legacy) -> initialize -> list_tools -> call_tool('fetch', arguments).
Client(mode=legacy) посылает initialize при входе в async context manager.
Это не прямой HTTP-запрос клиента и не встроенный webfetch.

Факты и применение:
1. https://docs.python.org/3/library/stdtypes.html#str.strip
   str.strip без chars возвращает строку без пробельных символов по краям. Исходная строка не изменяется.
   Это подтверждает нормализацию имён и обработку строки только из whitespace как пустого имени.
2. https://docs.python.org/3/library/stdtypes.html#set.discard
   set.discard удаляет элемент, если тот присутствует; это основание для безопасного удаления отсутствующего имени.
   Это подтверждает безопасную повторную отписку. Булев результат определяется нашим membership check, не возвратом discard.
3. https://docs.python.org/3/library/functions.html#sorted
   sorted возвращает новый отсортированный список из элементов iterable.
   Это подтверждает порядок результата list_subscribers и независимость выданного списка от множества.

Наблюдавшиеся ограничения запуска:
- Запуски в sandbox до handshake завершались ошибкой uv cache: Operation not permitted (os error 1). MCP-ответами они не считаются.
- При первом успешном чтении stdtypes SDK сообщил Failed to parse JSONRPC message from server:
  в stdout были посторонние startup-строки npm, включая 'added 38 packages, and audited 39 packages in 4s'.
  Несмотря на предупреждения, initialize/list_tools и валидный ответ fetch с isError=false были получены.
- Версия launcher package — mcp-server-fetch@2026.8.18; serverInfo отдельно сообщил mcp-fetch 1.30.0.
  Эти две фактические версии не отождествляются.
- Метка <error>Content truncated в адресных ответах — сообщение fetch о пагинации по max_length, а не isError=true.
  Определения strip и discard полностью присутствуют в сохранённых фрагментах.
