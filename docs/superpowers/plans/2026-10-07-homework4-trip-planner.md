# Домашняя работа 4: план разработки планировщика поездок

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Получить полностью готовую домашнюю работу 4: работающий собственный skill планирования поездок, собственный MCP, применённую среду агента, проверенные демонстрации и личную рефлексию.

**Architecture:** Skill собирает ограничения и проверенные расписания, вызывает собственный MCP `plan_departures` и объясняет до пяти вариантов. Один Python-модуль считает пересадки и время выхода; адаптер расписаний поставляет ему данные. Среда OpenCode и hook продолжают уже выполненную практику 4.

**Tech Stack:** Python 3.12+, uv, официальный MCP Python SDK со stdio, unittest, Ruff 0.16.10, установленный OpenCode 1.18.32, существующий JavaScript hook. Бесплатные транспортные источники; Яндекс Расписания — основной кандидат после проверки доступности и условий.

**Spec:** [Устройство и точный контракт](../specs/2026-10-07-homework4-trip-planner-design.md).

План подтверждён пользователем и реализуется. Галочки отражают проверенный
результат на 08.10.2026; личная рефлексия и согласование длинной прогулки
ещё не завершены. Главный пример: **Альпийский переулок → Малый Лужский каньон у
Плоского**. Пользователь согласен подключить API при бесплатном доступе.

## Приёмка по домашке: все 10 баллов

| Критерий задания | Что должно быть предъявлено | Где |
|---|---|---|
| AGENTS — 1 | Прочитанные актуальные правила и применение | `AGENTS.md`, `evidence/environment.txt` |
| Skill в среде — 1 | Реальная загрузка собственного skill | каталог skill, `evidence/skill.txt` |
| MCP в среде — 1 | Реальный вызов подключённого инструмента | `opencode.json`, `evidence/mcp.txt` |
| Hook — 1 | FAIL после правки и PASS после исправления, возвращённые агенту | hook, runner, `evidence/hook.txt` |
| Обоснование — 1 | Зачем каждый компонент нужен этой задаче | `REPORT.md` |
| Автоматизация skill — 1 | Сбор входа, проверка источников, расчёт и объяснение | skill и его ресурсы |
| Проверенный результат skill — 1 | Запуск и независимая проверка времени/пересадок | `evidence/skill.txt`, `evidence/real-route.md` |
| Полезный собственный MCP — 1 | Исходники инструмента расчёта | `trip_planner/server.py`, `planner.py` |
| Успех и ошибка MCP — 1 | Фактические протокольные вызовы | `tests/test_mcp.py`, `evidence/mcp.txt` |
| Рефлексия — 1 | Конкретные личные наблюдения пользователя | `reflection.md` |

Это карта покрытия критериев, а не обещание оценки. Домашка готова, когда
все строки подтверждены, реальный маршрут проверен и пакет можно запустить
и объяснить на защите. Наличие файлов без демонстрации не закрывает пункты.

## Порядок работы и объяснений

Основной порядок: 1 → 2 → 3 → 4 → 5 → 6 → 7. При ожидании ключа можно
завершить расчёт, MCP и быстрые проверки на обозначенных тестовых данных;
реальная приёмка остаётся зависимой от источников. Связанные компоненты
разумно реализовывать последовательно, независимое ревью и проверку
поведения skill — поручать отдельному агенту.

Перед этапом пользователь получает короткое объяснение его смысла; после —
что появилось, как это проверено и какой пункт домашки закрывается.
Показывать расчёт на примере редкой пересадки, чтобы пользователь мог
самостоятельно объяснить результат. Не объявлять всю домашку готовой до
демонстраций и рефлексии.
