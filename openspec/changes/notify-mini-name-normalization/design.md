# Design

## Context

См. `proposal.md` о цели и `../../specs/notify-mini/spec.md` о текущем контракте. В `service.py` три публичные функции и общее множество; до изменения есть восемь тестов. Нормализация имени повторяется в подписке и отписке.

## Goals / Non-Goals

**Goals:** Единая очистка имени; сохранение импортированной ссылки на состояние; доказанная совместимость; воспроизводимая локальная демонстрация персонального проекта.

**Non-Goals:** Новая архитектурная прослойка, новый протокол запуска, поддержка нестроковых аргументов и изменение правил сравнения имён.

## Decisions

1. Извлечь приватную `_normalize_name(name: str) -> str` в тот же модуль. Она один раз вызывает `strip`, проверяет пустоту и возвращает имя либо `ValueError("empty name")`. Оставить две копии проще по числу функций, но тогда изменение правила может разойтись между операциями. Отдельный класс или модуль для такой функции избыточен.
2. В `subscribe` и `unsubscribe` использовать результат helper; множество не переназначать. `set.discard` и существующие словари результатов сохраняются. `list_subscribers` не меняется.
3. До рефакторинга добавить четыре characterization tests публичного контракта. Они ожидаемо проходят на старом коде; это GREEN → REFACTOR → GREEN, а не заявление о RED при добавлении нового поведения. Проверка приватной функции ради искусственного RED не нужна.
4. Показать `python3 -i practices/practice_03/lab/demo/service.py` из корня и несколько операций в одном процессе. HTTP-процесс добавил бы другой продуктовый интерфейс и нарушил бы ограничение AGENTS. Отчёт прямо называет показ локальным запуском модуля, без утверждений о веб-сервисе.
5. Применить `skip_specs: true`: требований, меняющих поведение, нет. Основная spec — исходный снимок уже работающего сервиса. После приёмки change можно архивировать без синхронизации delta.

## Risks / Trade-offs

- Нормализация может потеряться в одной операции → проверки пробелов для обеих операций.
- Ошибочный ввод может очистить или заменить состояние → проверка непустого состояния после ошибки и сохранения импортированного множества.
- Проверки могут повторять реализацию → ожидаемые ответы заданы литералами, helper из тестов не вызывается.
- Термин «локальный сервис» в общей программе шире демонстрации модуля → явно показать фактический формат; решение о зачёте принимает преподаватель.

## Migration Plan

Миграция данных не требуется. Изменения локальны в `practice-05`; откат — вернуть один коммит рефакторинга. Результаты предыдущих занятий остаются неизменными.
