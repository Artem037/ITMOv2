# Notify Mini

## Purpose

Учебный сервис подписки хранит строковые имена в памяти одного Python-процесса. Эта спецификация фиксирует существующее поведение до рефакторинга; новых функций продукта она не вводит.

## Requirements

### Requirement: Нормализация имени

Операции `subscribe(name)` и `unsubscribe(name)` SHALL принимать строковое имя, удалять пробельные символы по краям и использовать очищенное имя. Если после очистки строка пуста, операция SHALL вызывать `ValueError("empty name")` без изменения множества подписчиков.

#### Scenario: Подписка с пробелами
- **WHEN** вызван `subscribe(" Ann ")`
- **THEN** результат равен `{"subscribed": True}`, а в множестве хранится `"Ann"`

#### Scenario: Отписка с пробелами
- **GIVEN** в множестве есть `"Ann"`
- **WHEN** вызван `unsubscribe(" Ann ")`
- **THEN** результат равен `{"unsubscribed": True}`, а `"Ann"` удалена

#### Scenario: Пустое имя при непустом состоянии
- **GIVEN** в множестве есть только `"Ann"`
- **WHEN** любая из двух операций получает `""` или `" \t\n"`
- **THEN** возникает `ValueError("empty name")`, а множество остаётся `{"Ann"}`

### Requirement: Повторная подписка

Операция `subscribe(name)` SHALL добавлять очищенное имя в общее множество и возвращать `{"subscribed": True}`, включая повторную подписку. Дубликаты SHALL отсутствовать.

#### Scenario: Два одинаковых имени
- **WHEN** дважды выполнена подписка `"Ann"`
- **THEN** оба результата равны `{"subscribed": True}`, а множество равно `{"Ann"}`

### Requirement: Безопасная отписка

Операция `unsubscribe(name)` SHALL возвращать `{"unsubscribed": True}`, если очищенное имя присутствовало, и `{"unsubscribed": False}`, если отсутствовало. Отсутствующее непустое имя SHALL обрабатываться без ошибки.

#### Scenario: Повторная отписка
- **GIVEN** выполнена подписка `"Ann"`
- **WHEN** дважды выполнена отписка `"Ann"`
- **THEN** первая возвращает `{"unsubscribed": True}`, вторая — `{"unsubscribed": False}`, а множество пусто

### Requirement: Независимый отсортированный список

`list_subscribers(query="")` SHALL возвращать новый список исходных имён в порядке стандартной сортировки строк Python без изменения подписок. Строковый запрос SHALL очищаться от пробелов по краям и находиться как подстрока имени без учёта регистра (Unicode caseless matching). Пустой запрос или вызов без аргументов SHALL возвращать весь список; отсутствие совпадений — `[]`. Изменение результата SHALL оставлять состояние сервиса неизменным.

#### Scenario: Сортировка и независимость результата
- **GIVEN** выполнены подписки `"Zoe"` и `"Ann"`
- **WHEN** запрошен список, затем вызывающий изменяет этот список
- **THEN** первоначально получено `["Ann", "Zoe"]`, а повторный запрос по-прежнему возвращает `["Ann", "Zoe"]`

#### Scenario: Нет подписчиков
- **WHEN** запрошен список пустого сервиса
- **THEN** результат равен `[]`

#### Scenario: Поиск подстроки без учёта регистра
- **GIVEN** подписаны `"Ann"`, `"Joanna"`, `"Bob"`, `"Straße"`
- **WHEN** передан запрос `"AN"`
- **THEN** результат равен `["Ann", "Joanna"]`

#### Scenario: Unicode сравнение
- **GIVEN** подписано имя `"Straße"`
- **WHEN** передан запрос `"STRASSE"`
- **THEN** результат равен `["Straße"]`

#### Scenario: Пробелы по краям запроса
- **GIVEN** подписаны `"Ann"`, `"Anna"` и `"Bob"`
- **WHEN** передан запрос `" \tAN\n "`
- **THEN** результат равен `["Ann", "Anna"]`

#### Scenario: Пустой запрос
- **GIVEN** подписаны `"Zoe"` и `"Ann"`
- **WHEN** запрос равен `""` или `" \t\n"`
- **THEN** результат равен `["Ann", "Zoe"]`, как при вызове без аргументов

#### Scenario: Совпадений нет
- **GIVEN** подписано только имя `"Bob"` либо список пуст
- **WHEN** передан запрос `"zz"`
- **THEN** результат равен `[]`

#### Scenario: Фильтр не меняет состояние
- **GIVEN** подписаны `"Ann"`, `"Anna"` и `"Bob"`
- **WHEN** получен результат для `"ann"`, затем вызывающий добавляет в него `"Zoe"`
- **THEN** новый результат для `"ann"` равен `["Ann", "Anna"]`, а полный список по-прежнему равен `["Ann", "Anna", "Bob"]`

### Requirement: Общее состояние в памяти

Публичные операции SHALL использовать тот же объект множества `subscribers`, который доступен через импорт из `service`. Состояние SHALL сохраняться между вызовами в одном процессе; хранение между запусками процесса не предоставляется.

#### Scenario: Существующая ссылка на состояние
- **GIVEN** вызывающий импортировал `subscribers` из `service`
- **WHEN** выполнена подписка `"Ann"`
- **THEN** импортированная ссылка по-прежнему является `service.subscribers` и содержит `"Ann"`
